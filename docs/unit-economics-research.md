# Vela: токени та unit economics

Дата перевірки: 23 листопада 2026. Рішення для локального продукту: **1 000 токенів = $1, базова націнка 75% на API-собівартість**, округлення вгору до цілого токена на один результат. Оплата поки тестова. Це не підключення еквайрингу й не дозвіл запускати платні генерації.

Інтерактивний [калькулятор](unit-economics.html), [132 сценарії в CSV](unit-economics.csv), [дослідження Voplica](voplica-pricing-research-2026-11-23.md). Відтворення таблиць: `cd frontend && node scripts/unit-economics.mjs`.

## 1. Націнка, маржа й гроші, які залишаються

`Роздрібна ціна P = API-собівартість C × (1 + націнка)`.

| Націнка | Множник | Валова маржа до інших витрат |
| --- | ---: | ---: |
| 70% | 1.70 | 41.18% |
| **75%** | **1.75** | **42.86%** |
| 80% | 1.80 | 44.44% |

75% націнки не означає 75% прибутку. Після API залишаються комісія приймання оплати, зберігання/трафік, платні помилки, повернення, подарункові токени та податки. Зарплати, маркетинг, юридичні витрати й постійні серверні витрати — додатково.

Базова формула contribution на результат:

`P − C − P × комісія% − P × фіксована_комісія / розмір_пакета − змінна_інфраструктура`.

У калькуляторі також є сценарії повернення виручки, платних невдач та включеного VAT/sales tax. Це припущення для аналізу, не податкова рекомендація. Помилка, за яку провайдер нічого не списав, не додає API-собівартості. Повторна генерація на прохання користувача після успішного результату — нова оплачувана генерація, а не технічний retry.

## 2. Перевірені тарифи BytePlus і референси

Поточна інтеграція підтримує Seedream 5 Pro та Seedance 2.5. Каталог інших моделей нижче — порівняння економіки, не твердження, що всі вони вже ввімкнені.

Seedream 5 Pro: для поточних 1K виходів Vela API-ціна $0.045; для 2K — $0.09. Перший input безкоштовний, наступні коштують $0.003 кожен. Кожен результат Vela — окремий API-запит, тому доплата за inputs повторюється для кожного output.

Для Seedance використано $10.70 за мільйон токенів без відеовходу та опубліковані оцінки 9 600/21 600 токенів за секунду для 480p/720p. Фактичні токени можуть відрізнятись через розміри/кадри. Користувачу фіксуємо прийняту ціну; різниця витрат залишається ризиком Vela. Звичайний image reference не створює окремої фіксованої доплати. Вхідне відео тарифікується інакше та зараз не приймається Vela як відеореференс. [Офіційний прайс і формули BytePlus](https://console.byteplus.com/ark/region:ap-southeast-1/docs/model-pricing).

Приклад: 6 підключених reference assets → 5 платних inputs для Seedream. Character sheet — один input; чотири фото, з яких раніше склали sheet, не дорівнюють чотирьом надісланим inputs. Рахувати потрібно фактичні asset references після серверного вирішення зв'язків. За вписаний у prompt текст `@name` без доданого asset не можна стягувати плату як за референс.

## 3. Ціна генерації при 70%, 75%, 80%

Таблиця — наш розрахунок з ціни API. `$0.079 / 79` означає $0.079 або 79 токенів за один результат.

| Генерація | API, $ | 70%: $ / токени | 75%: $ / токени | 80%: $ / токени |
| --- | ---: | ---: | ---: | ---: |
| Seedream 1K, 0–1 refs | .045 | .077 / 77 | **.079 / 79** | .081 / 81 |
| Seedream 1K, 2 refs | .048 | .082 / 82 | **.084 / 84** | .087 / 87 |
| Seedream 1K, 6 refs | .060 | .102 / 102 | **.105 / 105** | .108 / 108 |
| Seedream 2K, 0–1 refs | .090 | .153 / 153 | **.158 / 158** | .162 / 162 |
| Seedream 2K, 6 refs | .105 | .179 / 179 | **.184 / 184** | .189 / 189 |
| Seedance 2.5, 480p, 5s | .5136 | .874 / 874 | **.899 / 899** | .925 / 925 |
| Seedance 2.5, 720p, 5s | 1.1556 | 1.965 / 1965 | **2.023 / 2023** | 2.081 / 2081 |
| Seedance 2.5, 720p, 10s | 2.3112 | 3.930 / 3930 | **4.045 / 4045** | 4.161 / 4161 |
| Seedance 2.0, 720p, 5s | .756 | 1.286 / 1286 | **1.323 / 1323** | 1.361 / 1361 |
| Seedance 2.0 Fast, 720p, 5s | .6048 | 1.029 / 1029 | **1.059 / 1059** | 1.089 / 1089 |
| Seedance 2.0 Mini, 720p, 5s | .378 | .643 / 643 | **.662 / 662** | .681 / 681 |

За count=4 роздрібна сума дорівнює 4 × округлена ціна одного output. Наприклад, чотири 1K з шістьма refs = 420 токенів, а не 105. Округлення дає фактичну націнку трохи вище цільової; ми не рекламуємо точні 75.000% на кожен запит.

Порівняння передбачає базовий прайс без акцій і контрактних знижок. Промо не закладаємо в постійну роздрібну ціну. Для комерційної Seedance-пропозиції потрібна калібровка на фактичних `usage` для підтриманих aspect ratios та adaptive frames.

## 4. Voplica: кредит провайдера не дорівнює токену Vela

Публічний каталог Anytime: $7/500 кредитів, $20/1500, $65/5000. Для безпечного базового розрахунку беремо **$0.014 за кредит провайдера**, без припущень про повне використання підписки. Провайдер повертає milli-credits: `cash cost = netChargedMilli / 1000 × 0.014`. [Каталог Voplica](https://voplica.com/pricing), [схема API](https://github.com/voplica/api).

Workflow показує середній hint 37 кредитів та стартовий резерв 10 кредитів. **Жодне число не є ціною 5-секундного MiniMax або верхньою межею списання.** Hosted models оплачуються за фактичні обчислення; inputs можуть вплинути на runtime. Не вигадуємо фіксовану плату за кожен референс. [Білінг Voplica](https://docs.voplica.com/billing/).

Якщо продати результат за 907 токенів ($.907), чутливість до реальної витрати така:

| Фактичні кредити Voplica | API, $ | Валова маржа за ціни $.907 |
| ---: | ---: | ---: |
| 20 | .280 | 69.13% |
| 37 | .518 | 42.89% |
| 60 | .840 | 7.39% |
| 80 | 1.120 | **−23.48%** |

Тому 907 токенів не запущено як гарантований MiniMax-тариф. У продукті для неперевіреної ціни показується **Pricing pending**, генерація блокується. Потрібні оплачений benchmark або письмова верхня межа від провайдера. Також його умови вимагають дозволу на resale; API-ключ сам по собі його не підтверджує. Див. [повне дослідження та план benchmark](voplica-pricing-research-2026-11-23.md).

## 5. Contribution після витрат

База: 75% markup, еквайринг 2%, умовна змінна інфраструктура $.002/image та $.01/video; без повернень, непрямих податків, зарплат та CAC. Інфраструктурні числа — припущення для чутливості, не виміряний AWS bill. Комісія 2% відповідає опублікованому прикладу WayForPay, який ще не підключено. [Тариф провайдера](https://wayforpay.com/uk).

| Результат | Роздріб | API | Платіж | Інфраструктура | Contribution | Частка |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1K без платних refs | .079 | .045 | .00158 | .002 | **.03042** | 38.51% |
| 1K, 6 refs | .105 | .060 | .00210 | .002 | **.04090** | 38.95% |
| Seedance 2.5 720p 5s | 2.023 | 1.1556 | .04046 | .010 | **.81694** | 40.38% |

Це не чистий прибуток. При $500 постійних місячних витрат та 38% contribution потрібно приблизно $1 316 виручки лише для покриття цих витрат, до CAC і податків. Розподіл генерацій між моделями змінює середню contribution. Пакетні надходження — грошовий потік; невитрачені токени залишаються майбутнім зобов'язанням надати послугу. Не використовуємо breakage як умову прибутковості.

## 6. Пакети та подарунок

| Пакет | Ціна | Токени | Знижка |
| --- | ---: | ---: | ---: |
| Starter | $10 | 10 000 | 0% |
| Creator | $25 | 25 000 | 0% |
| Studio | $50 | 50 000 | 0% |

Не додаємо прихованих бонусів у великі пакети: вони знижують ефективну націнку. Разовий welcome = **500 токенів**, що дає шість 1K картинок без платних refs (474 токени) або два 2K результати з шістьма refs (368). П'ятисекундне Seedance 2.5 навіть у 480p потребує 899 токенів, отже відео не обіцяється у безкоштовному welcome.

За повного використання welcome його API-бюджет ≈ $0.286 на акаунт, до інфраструктури. 1 000 безкоштовних акаунтів — до ≈ $286 API-витрат у цій моделі. Подарунок видається один раз на owner, не на login; це не захист від створення багатьох різних акаунтів. Перед публічним увімкненням потрібні обмеження бюджету, контроль signup abuse та моніторинг.

Сценарій першої покупки: всі куплені + 500 подарункових токенів витрачені, markup75%, fee2%, без інфраструктури:

| Пакет | API з welcome | Contribution до інших витрат |
| --- | ---: | ---: |
| $10 | ≈ $6.00 | **$3.80 / 38.00%** |
| $25 | ≈ $14.57 | **$9.93 / 39.71%** |
| $50 | ≈ $28.86 | **$20.14 / 40.29%** |

Токени — непереказні одиниці використання Vela, без cash-out. Наразі строк згоряння не запроваджено. Реальні правила повернень/податків/строку дії мають бути опубліковані перед прийманням грошей; локальний тестовий checkout не створює справжню покупку.

## 7. Реалізація й межі готовності

- Баланс належить авторизованому owner у PostgreSQL; браузер не вирішує скільки нарахувати. Welcome і confirm ідемпотентні.
- Buy tokens у навігації веде на `/billing`; вибір пакета → `/billing/checkout/:id` → явне підтвердження тестової покупки → оновлений баланс та запис у ledger. Платіжні реквізити не збираються.
- Ціна зберігається незмінним snapshot при admission. Кошти резервуються атомарно для всіх takes. Доставлений результат списує свій резерв, підтверджена невдача повертає його. Частковий успіх оплачується тільки за доставлені результати.
- Невідомий результат платного POST або тимчасова втрата зв'язку не означає refund: утримуємо резерв до reconciliation та не запускаємо повторну платну генерацію.
- Test checkout вимкнений у production незалежно від прапорця. Тестові покупки не фінансують реальний inference без окремого локального override; в production це заборонено. Реальні еквайринг, webhooks, chargebacks і повернення грошей ще не реалізовані.
- BytePlus/Voplica generation flags залишаються вимкненими. Факт роботи token checkout не означає верифікацію якості/собівартості живої генерації.

Рішення: застосувати 75% як базову політику, почати з фіксованих пакетів без знижок; за потреби підняти до 80% після вимірювання paid failure, зберігання та реального платіжного тарифу. Для Voplica не продавати некалібрований fixed-price inference.
